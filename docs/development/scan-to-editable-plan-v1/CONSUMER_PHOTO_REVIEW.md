# Consumer photo correction boundary

The original source and original rendered page remain retained private assets. A calibration may add a deterministic constrained projective correction before the existing affine registration. Its fitting spans and independent checks are source observations, not room geometry. Six fitting spans, at least two held-out spans and one explicitly confirmed square corner constrain the proposal; an adequate affine model prevents unnecessary perspective correction. Duplicate spans cannot count as independent checks. Residual acceptance is evaluated by inverse projection to original pixels, including any prior rendering normalization.

The source review always selects on the original rendered page. The before/after image uses the same matrix as server rendering. Registered editor/export underlays consume a corrected owner-scoped derivative URL with affine image placement, avoiding a projective mapping disguised as an ordinary rectangular underlay. Source anchors and calibration measurements stay in the original page frame. Original source dimensions, hash and identity are preserved.

Unaccepted measurement drafts and unresolved source spans are stored on the existing document as review data/reference annotations. They can be corrected before metric geometry exists. A pending span does not create a room, close a connection or establish an opening host. Existing manual room/opening tools remain explicitly assisted geometry creation.

`photo-review` runs local extraction using retained observations and a corrected private image. External semantic classification is forbidden by its local-only context. Captured hints are proposals and still go through source registration; confirmed source measurements supply scale. The output rebinds anchors to the original source and stays needs_review with a critical incomplete-boundary issue. No whole-plan recovery is inferred from a fallback's internal promotion flag.

Changing registration once geometry exists creates a separate import job. Before committing that child, the route locks the retained source then parent job and checks owner, candidate version, status, expiry and deletion again. Parent candidates and applied designs are never updated. Parent source annotations survive, and rendered assets and retained observations receive child-owned derivative IDs without extending retention. Generic source observations are archived as retention-managed JSON derivatives, not public fixtures.

Current limitations: the original apartment returns a partial subset (current counts below). Pending arbitrary boundary spans do not yet assemble a complete central room. Thickness, wall classification, unidentified symbols and several connections remain unresolved. The local acceptance preview uses a fixture identity and isolated database; production authentication and full recognition are not claimed. No new model/provider integration is enabled.

The next source-association correction prevents ambiguous OCR stroke glyphs from vetoing long wall rails. Ordinary OCR text excludes only strokes contained in its box; separately classified room/dimension text keeps its semantic exclusion. Raw OCR remains reference evidence. This addresses an observed association failure independently of perspective correction.

After correction, bounded local solid-stroke/paired-rail candidates become original-frame reference annotations, including open and disconnected spans. They do not enter the canonical wall graph. Multi-rail ambiguity, text, dimension rulers and fixtures cause abstention; there is no gap closure. Locally supported opening endpoints also remain visible even when they lack a canonical host. Consumer-edited annotations take precedence over regenerated evidence, while stale untouched automatic boundary proposals are replaced. Choosing a pending span highlights it and loads its endpoints for correction without requiring existing walls.

These counts are not complete-plan accuracy: shared wall reconciliation, assumed thickness, central space, connections and the separate doorway still need work. No consumer confirmation is inferred from automatic extraction or scripted UI selection.

A consumer can classify a selected reference as an interior item. The existing annotation configuration tag `consumer-source-interior-item-v1` records that decision without a new geometry type. On a separate photo recomputation, only a matching source/page opening-proposal ID is suppressed; ordinal IDs and raw retained observations remain unchanged. The classification does not erase raster pixels, mask nearby boundaries or modify existing walls/openings. Reclassifying the mark clears the exclusion. Review changes preserve the earlier proposal evidence and append the review history. Arbitrary interior-item reference marks remain annotations; they do not define an inferred exclusion region.

The server review sanitizer retains its own prior reference evidence and history, discards client-authored provenance, and appends an authenticated `corrected` event. Source reference changes have zero geometry confidence, including incomplete draft saves. Unchanged marks retain their stored history. Canonical entity confirmation behavior is unchanged; no reference classification grants an opening host or acceptance tier.

Explicit history selection of a different active review starts a fresh assistant session, even when returning to the original parent after a child was activated internally. This clears stale candidate state and aborts the previous session's actions. Choosing “Continue below” on the already active review does not reset its unsaved consumer corrections.

Source review defaults to canonical proposals plus the explicitly selected/focused reference mark.
